## 2026-06-01 — Phase 5 GUI 驗收 + playable snapshot 收尾
Type: Implementation + Verification
Phase: Phase 5
Feature: Editor GUI 驗收、`buildPlayableSnapshot`、自製關卡匯出 / 試玩
Commit: (待提交)

### Context
上一輪已把 editor 的滑鼠版功能做齊，也補了 runtime path prompt / `--menu` / 數字框微調；但程式分數仍卡在 editor 的 10% 尚未 GUI 入帳。進一步檢查時發現 `PLAY` / `EXPORT` 直接吃 live editor state 會有一個口試上很危險的語意問題：如果設計者先把解答零件擺在盤上，再按 `P`，遊戲可能會從「已經排好解答」的狀態開始。

### AI Contribution
- 先補 core：在 `Editor` 加 `buildPlayableSnapshot(Board&, vector<Part>&)`，把目前設計轉成真正可玩的關卡快照。
- 規則是：保留 board 尺寸、顏色數、固定格、不可放置格、以及列欄數字；但把所有暫時擺在盤上的 `OCCUPIED` 格清成 `EMPTY`，並把每個 part 送回 tray（`placed=false`、`row=partIndex`、`col=-1`、`rotate=CW_0`）。
- `exportEditorLevel(...)` 與 editor 的 `PLAY` 流程都改成先建快照，再分別走 `LevelWriter::write(...)` 與 `Game::init(...)`，避免「設計態」和「遊玩態」混在一起。
- 接著寫 PowerShell GUI 驗收腳本，用 Win32 `ClientToScreen` / `SetCursorPos` / `mouse_event` + `WScript.Shell.SendKeys` 自動跑 editor：從 menu 按 `E` 進入、stepper 改大小/顏色數、PART DESIGNER 畫 2 格零件並 `ADD`、PLACE 到盤面、點數字框微調後移除重擺以恢復自動推導、再依序測 BLOCK / FIX / ERASE、`EXPORT`、`PLAY`、最後 `F` 自動解。

### Human Decision / Review
使用者明確要「把程式實作補完」，因此這輪直接把 editor 剩餘 10% 的程式面驗收到可誠實勾分，不再先停在「headless 都對，但 GUI 沒跑」的中間狀態。

### Details
- [src/core/Editor.h](../src/core/Editor.h) / [src/core/Editor.cpp](../src/core/Editor.cpp)：新增 `buildPlayableSnapshot(...)`。
- [src/main.cpp](../src/main.cpp)：`EXPORT` 與 `PLAY` 都改走 playable snapshot，不再直接把 live editor 盤面送進 `Game::init(...)`。
- [docs/STATUS.md](../STATUS.md)：Phase 5 三項入帳，總分改為 58.0%。
